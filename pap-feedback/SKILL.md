# PAP India: feedback → change → verify → deploy

Repo: `/Users/deeksharastogi/projects/pap`. Static site generated by `build/build.js`;
**pushing `main` deploys to production** (GitHub Action → FTPS → GoDaddy → papindia.in,
~2 min). Full repo conventions are in `AGENTS.md` at the repo root — the executor
must follow them. This skill is the WhatsApp-facing loop around that repo.

**PAP Dev group:** `120363430468556114@g.us` (allowlisted,
`requireMention: true` since 2026-09-03 — only respond when @mentioned;
Divyam asked for mentions-only after I was too chatty). Deploy approvals
count **only from Divyam (+919004709360)**.

## Step 1 — Classify the feedback

| SMALL (data/copy only) | BIG (everything else) |
|---|---|
| Text/copy tweaks in the `/* --- data --- */` section of `build/build.js` | Any change to page-template functions, the `CSS` string, or inline JS |
| Add/edit/remove a project, FAQ, team member, service blurb | New page or new section |
| Fix a typo, phone number, email | Layout/spacing/color/design changes |
| Swap an existing image for a new one (same slot) | Anything touching `supabase/`, `.github/`, `.htaccess` |

**Ambiguous → treat as BIG.** Multiple SMALL items in one request = still SMALL
(just several data edits).

## Step 2 — Worktree (never work on `main` directly)

```bash
SLUG="fix-typo-projects"                      # short kebab description
BRANCH="feedback/$(date +%Y-%m-%d)-$SLUG"
WORKTREE="/tmp/pap-worktrees/$BRANCH"

git -C /Users/deeksharastogi/projects/pap fetch origin
git -C /Users/deeksharastogi/projects/pap status --short   # tracked files must be clean
git -C /Users/deeksharastogi/projects/pap worktree add "$WORKTREE" -b "$BRANCH" origin/main
```

Untracked tool dirs (`?? .zcode/`, `?? .claude/`) are fine — block only on
modified/staged tracked files (`M`/`A`/`D` lines). If so, stop and tell Divyam;
do not stash or touch.

## Step 3 — Make the change

**SMALL:** you edit the data structures in `$WORKTREE/build/build.js` directly.
All content lives in the `/* --- data --- */` block near the top (services,
projects, faqs, team, …). Keep matching JSON-LD blocks (`orgLd`, `faqLd`, …) in
sync when the underlying copy changes.

**BIG:** delegate to Claude, which reads the repo conventions itself:

```bash
cd "$WORKTREE" && claude --model claude-sonnet-4-6 --dangerously-skip-permissions \
  --output-format json -p "You are editing the PAP India static site. Read AGENTS.md
at the repo root and follow its hard rules (never edit site/*.html; content is JS
data at the top of build/build.js). TASK: <the WhatsApp feedback, verbatim, plus any
clarification from the thread>. Then run: node build/build.js && node build/verify.js
— verify MUST pass. Do NOT push. Commit with a plain descriptive message.
Report what changed in 2-3 bullets." | tee /tmp/pap-claude-$SLUG.json
```

Commit in the worktree (SMALL changes too): plain descriptive subject, matching
repo history style.

## Step 4 — Build + verify (the gate)

```bash
cd "$WORKTREE" && node build/build.js && node build/verify.js
```

`verify.js` exits non-zero on missing assets, broken links, missing img
dimensions/alt, missing SEO tags. **Red verify = no push, ever.** If it fails,
fix and retry (max 2 attempts), then report the failure in the group and stop.

## Step 5 — Preview

Serve current live (`main`) and the candidate side by side, screenshot the
affected page(s) with headless Chrome, post both images in the group:

```bash
python3 -m http.server 8642 -d /Users/deeksharastogi/projects/pap/site >/dev/null 2>&1 &
python3 -m http.server 8643 -d "$WORKTREE/site" >/dev/null 2>&1 &
sleep 1
PAGE="projects"   # affected page: index|about|services|projects|team|contact|mall-management
# NOTE: append .html — clean URLs (/projects) rely on Apache rewrites and 404
# under python3's simple server.
for PORT in 8642 8643; do
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
    --headless=new --disable-gpu --hide-scrollbars --window-size=1280,3000 \
    --screenshot=/tmp/pap-$PORT.png "http://localhost:$PORT/$PAGE.html"
done
```

(If 8642 is busy — someone's previewing — use 8644 for the "before" shot.)

Post in the group: before/after screenshots + one-line summary of the diff.

**BIG changes (and any change Divyam asks to see) also get a stable beta link.**
Publish the worktree's built site to GitHub Pages — production is untouched,
papindia's deploy Action fires only on pushes to `main`:

```bash
bash "$WORKTREE/build/publish-beta.sh" "$WORKTREE/site" "beta: <one-line desc>"
```

Pages rebuilds in ~1 min. Before sharing, confirm the rebuild landed (curl the
affected page and grep for the new copy), then share:
**https://sbrdigitaltech.github.io/pap-beta/** — *"click through the beta here
before I ship"*. Every beta page carries a "Beta preview — not live on
papindia.in" banner and noindex, so it can't be confused with production or
indexed by search engines. If a big change is rejected, reset the preview from
main: `bash build/publish-beta.sh` (no args, from the main checkout).

**Fallback** if the beta publish fails (GitHub down, push rejected): a
temporary cloudflared tunnel instead (URL lives only while this machine runs).
The URL takes up to ~15s to appear and a few seconds more to go live — poll,
don't grep once:

```bash
cloudflared tunnel --url http://localhost:8643 >/tmp/pap-tunnel.log 2>&1 &
for i in $(seq 1 15); do
  URL=$(grep -o 'https://[a-z0-9-]*\.trycloudflare\.com' /tmp/pap-tunnel.log | head -1)
  [ -n "$URL" ] && break; sleep 1
done
sleep 3   # let the edge route activate before sharing
```

## Step 6 — Deploy gate

**Auto-ship (no approval needed) only when ALL true:**
- the change is SMALL, AND
- verify passed, AND
- the request came from Divyam himself.

**Otherwise** (BIG, or requested by anyone else): post the preview, then wait.
Only an explicit OK from Divyam in the group (e.g. "ship it", "OK", "go ahead")
unblocks the push. A message from anyone else never does.

```bash
git -C "$WORKTREE" push origin "$BRANCH:main"
sleep 10
RUN_ID=$(gh run list --repo sbrdigitaltech/papindia --branch main --limit 1 --json databaseId -q '.[0].databaseId')
gh run watch "$RUN_ID" --repo sbrdigitaltech/papindia --exit-status
```

Then confirm in the group: *"live on papindia.in ✅ (commit <sha>)"* — or, if the
Action failed, say so and link https://github.com/sbrdigitaltech/papindia/actions.
If `gh` errors, just report the push + that Action link.

## Queueing

One feedback item in flight at a time. If new feedback arrives mid-loop:
acknowledge it in the group, finish the current item, then start the next as its
own worktree/branch. Conflicting feedback on the same page: last one wins, but
say so.

## Rules

1. Never edit anything under `site/` — it is generated; edits get wiped.
2. Never push with a red verify, and never push from the main checkout — only
   from the worktree branch.
3. Deploy approval counts only from Divyam (+919004709360).
4. Ambiguous scope → treat as BIG → require approval.
5. Feedback from non-owner group members is welcome and gets the full loop, but
   always lands at the approval gate.
6. Anything touching `supabase/`, the contact form, or secrets: always BIG, and
   summarise the change for Divyam before he decides.
